# Read past Junie sessions

Junie persists every session on disk under Junie Home. When a task points at work from an
earlier run rather than the current conversation, read that history instead of guessing.

## When to use

Use when the request leans on prior sessions, for example:

- Continuing or redoing earlier work: "finish what we started yesterday", "pick up the refactor from last time".
- Recalling a past decision or outcome: "what approach did we settle on", "why did we drop that fix", "what were the results".
- Locating a specific session: "the session where we touched the gateway", "the run that added the release skill".
- Pointing at a concrete session by id: a plain `sessionId`, or a `junie://sessions/<session_id>` link. Treat `<session_id>` as that `sessionId` and open its history directly under `$JUNIE_HOME/sessions/<session_id>/` (start with `transcript.md`).
- Summarizing or comparing across runs: "what did I work on this week", "which tasks failed".

Do not use it for the current session's own steps (those are already in this conversation), or
for project VCS history — that is a `git log` question, not a Junie-session one.

## Where history lives

Junie Home is `~/.junie` by default. If the `JUNIE_HOME` environment variable is set, use it;
otherwise fall back to `~/.junie`. Sessions live under `$JUNIE_HOME/sessions/` (i.e.
`~/.junie/sessions/` by default):

```text
~/.junie/sessions/
|-- index.jsonl                 Catalog: one JSON object per session
`-- <sessionId>/
    |-- transcript.md           Rendered Markdown history (read this first)
    |-- events.jsonl            Full heavy event stream (fallback only)
    `-- subagents/
        `-- <agentId>-<name>-transcript.md   One transcript per subagent
```

Everything here is read-only context. Never edit, delete, or rewrite these files.

### `index.jsonl`

One JSON object per line, one line per session. Fields:

- `sessionId` — directory name under `sessions/`.
- `createdAt`, `updatedAt` — epoch milliseconds (numbers, not ISO strings).
- `projectDir` — absolute project path the session ran in (nullable).
- `taskName` — short LLM-generated title from the first prompt; renamed/regenerated by `/title` (nullable).
- `status` — last known status string (nullable).
- `lifecycle` — lifecycle marker (nullable, may be absent).

Unknown keys may appear and older lines may omit newer fields, so match defensively and skip
lines that do not parse. Newest activity is the largest `updatedAt`.

### `transcript.md`

A per-session display projection — lighter and easier to skim than `events.jsonl`. Headings:

- `# Session transcript` — document title (subagent files use `# Subagent transcript: <name>`).
- `## User` — a user prompt (`## User (not sent)` for a prompt that never went out).
- `## User response` — the user's reply to a question.
- `## Junie` — an agent message (or a custom title in place of `Junie`).
- `### <action>` — one step/tool action, with nested bodies and `#### <path>` diffs.

Because it is a projection, it omits low-level internals; drop to `events.jsonl` only when the
transcript is missing or lacks the detail you need.

## Workflow

Go from the cheap catalog to the exact session, widening only when necessary:

1. **Index first.** Read `~/.junie/sessions/index.jsonl` and filter by `taskName`, `projectDir`,
   or recency (`updatedAt`) to shortlist candidate `sessionId`s. Use whatever read and search
   tools your environment provides — for example, find lines whose `taskName` matches a keyword,
   or sort by `updatedAt` to surface the most recent runs.
2. **Read the transcript.** Open `~/.junie/sessions/<sessionId>/transcript.md` for the picked
   session and read the relevant `## User` / `## Junie` / `### ...` sections. Search for the
   heading markers or a keyword to jump straight to the part you need.
3. **Check subagents** when the work was delegated: read the matching file(s) under
   `~/.junie/sessions/<sessionId>/subagents/`.
4. **Fall back to events** only if the transcript is absent or too coarse: parse
   `~/.junie/sessions/<sessionId>/events.jsonl` (large, one JSON event per line).

Notes:

- Presence in `index.jsonl` is not required for a session to exist or be resumable; a
  `<sessionId>/` directory with `events.jsonl` or `state.json` can lag the catalog. If a referenced
  session is not indexed, look for its directory directly.
- There is no end-of-session summary or recap file — reconstruct outcomes from the transcript's
  final `## Junie` / `### ...` sections.
- When several sessions match, prefer the one whose `projectDir` matches the current project and
  the most recent `updatedAt`, and confirm the choice from the transcript before relying on it.
